# PartyCare Click-Cast Review Contract

## Submission Status

PartyCare is a **review candidate**. Its click-cast integration is disabled by default and must remain disabled until HorizonXI staff approve the exact public source revision. HorizonXI’s published rules require custom addons to be publicly available and approved before use.[1] [2]

## Interaction Contract

A click-cast request is valid only when all of the following conditions are true:

| Requirement | Enforcement |
|---|---|
| A person clicks a specific action button | Requests originate only from the ImGui button callback |
| A person previously selected a visible party member | The model requires explicit member selection |
| The action is explicitly configured and enabled | Bindings are schema-validated by identifier, label, and spell text |
| The integration review gate is manually enabled | `review_click_cast_enabled` defaults to `false` |
| The request is singular | One UI click yields at most one `MANUAL_CLICK_CAST_REQUEST` audit record |

## Prohibited Behavior

PartyCare must not add timers, repeated casts, proximity-based casts, health-threshold casts, packet operations, input injection, target scanning, target-selection loops, event-driven reactions, queues, or unattended execution. HP thresholds remain **visual-only** triage cues.

## Review Boundary

The package implements a guarded review adapter that records a one-shot cast request payload for inspection. It does not send a chat command, select a target, or cast in the client. Any future approved execution adapter must remain narrow: it may consume only an explicit `MANUAL_CLICK_CAST_REQUEST` generated by the same frame’s user click and must be separately reviewed by HorizonXI staff.

## Requested Staff Questions

The review submission should ask staff to rule on the following exact behavior:

1. May a user click a named action in a custom party frame to issue one configured spell request for an explicitly selected visible party member?
2. Is the proposed public source acceptable if it contains no timers, no auto-targeting, no packets, no input injection, no threshold-based actions, and no event-driven casts?
3. If approved, what Ashita command-dispatch mechanism and target notation, if any, does HorizonXI permit for that user click?
